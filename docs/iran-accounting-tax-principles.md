## 1. چگونه از این سند استفاده کنیم

1. قبل از تغییر poster / درخت حساب / UI حسابداری، بخش مربوط به همان رویداد را بخوانید.  
2. همیشه دو لایه را جدا نگه دارید:  
   - **دفتر حسابداری** (استاندارد ایران)  
   - **مالیات** (ق.م.م + VAT + مؤدیان)  
3. اگر تعارض بود: نرم‌افزار اول دفتر درست بسازد؛ گزارش/افشا برای فاصلهٔ مالیاتی.  
4. تصمیم‌های قطعی محصول در جداول «تصمیم وبینو» آمده‌اند؛ تغییرشان نیاز به آپدیت همین سند دارد.

## 2. اصول پایه حسابداری دوطرفه

1. **معادله اساسی:** دارایی = بدهی + سرمایه (+ سود انباشته اثر سود دوره).  
2. **هر سند متوازن است:** جمع بدهکار = جمع بستانکار (تلورانس وبینو: ۰٫۰۱ تومان).  
3. **حساب دائم** (ترازنامه): نقد، موجودی، طلب، بدهی، سرمایه — به دوره بعد منتقل می‌شود.  
4. **حساب موقت** (سود و زیان): درآمد، بهای تمام‌شده، هزینه — در بستن دوره صفر می‌شود.  
5. **شناخت تعهدی (تا حد مدل فروشگاه):** درآمد با تحقق فروش؛ هزینه با وقوع/تطابق — نه فقط با جابه‌جایی نقد.  
6. **تطابق:** بهای کالای فروش‌رفته هم‌زمان با درآمد همان فروش.  
7. **احتیاط:** زیان محتمل زودتر از سود تحقق‌نیافته شناسایی می‌شود.  
8. **ثبات رویه:** روش بهای موجودی (مثلاً FIFO) را بی‌دلیل عوض نکنید.  
9. **تفکیک شخصیت:** مال فروشگاه از مال شخصی مالک جدا است.  
10. **رویداد عملیاتی یک‌بار:** در وبینو فروش/خرید/هزینه در جداول عملیاتی ثبت می‌شود؛ دفتر از poster ساخته می‌شود (منبع حقیقت دوگانه عمدی نیست).

## 3. چارچوب استانداردها و قوانین ایران

### استانداردهای حسابداری (نمونه مرتبط با فروشگاه)

| شماره / موضوع | کاربرد در وبینو |
|---------------|-----------------|
| مفاهیم نظری / ارائه صورت‌های مالی | ساختار ترازنامه و سود و زیان |
| درآمد عملیاتی / استاندارد ۴۳ (قرارداد با مشتری) | زمان شناخت فروش: انتقال کنترل کالا به مشتری |
| استاندارد ۸ — موجودی مواد و کالا | خرید، FIFO، ضایعات، اقل بها و NRV |
| مخارج تأمین مالی (۱۳) | معمولاً خارج از دامنه فروشگاه کوچک |
| دارایی ثابت مشهود | هزینه نوع «سرمایه» / `12101` |
| ذخایر و بدهی احتمالی | مطالبات سوخت‌شده / دعاوی (آینده) |
| گزارشگری میان‌دوره‌ای | بستن میان‌دوره |

### قوانین و مقررات مالیاتی کلیدی

| منبع | کاربرد |
|------|--------|
| ق.م.م ماده ۹۵ + آیین‌نامه | دفاتر، اسناد، گروه‌بندی مشاغل |
| ق.م.م مواد ۱۴۷ و ۱۴۸ | هزینه قابل قبول عملکرد |
| ق.م.م ماده ۱۴۹ | استهلاک (جدول مصوب) |
| قانون مالیات بر ارزش افزوده | اعتبار خرید، مالیات فروش |
| قانون پایانه‌های فروشگاهی / سامانه مؤدیان | صورتحساب الکترونیکی |

### اصل طلایی

**ثبت حسابداری ≠ پذیرش مالیاتی خودکار.**  
همه چیز در دفتر ممکن است درست باشد ولی ممیز رد کند (مستند، متعارف، ارتباط با درآمد، صورتحساب).

## 4. کدینگ و صورت‌های مالی

### درخت پیشنهادی وبینو (سطح گروه)

| کد | نام | نوع |
|----|-----|-----|
| ۱ | دارایی‌ها | دائم / بدهکار |
| ۲ | بدهی‌ها | دائم / بستانکار |
| ۳ | سرمایه | دائم / بستانکار |
| ۴ | درآمدها | موقت / بستانکار |
| ۵ | بهای تمام‌شده | موقت / بدهکار |
| ۶ | هزینه‌ها | موقت / بدهکار |

جزئیات معین/تفصیلی در `ChartOfAccountsSeeder` و بخش ۲۳.

### صورت‌های مالی حداقلی فروشگاه

1. **تراز آزمایشی** — گردش و مانده همه حساب‌ها  
2. **دفتر حساب** — آرتیکل‌های یک حساب  
3. **سود و زیان** — درآمد − بهای تمام‌شده − هزینه  
4. **ترازنامه** — دارایی / بدهی / سرمایه (+ تطبیق نقد عملیاتی)

## 5. فروش و درآمد

### اصل شناخت

طبق رویکرد استاندارد درآمد (و راهنمای استاندارد ۴۳): درآمد وقتی شناسایی می‌شود که **کنترل کالا/خدمت به مشتری منتقل شده** باشد. صدور فاکتور یا دریافت وجه به‌تنهایی معیار نهایی نیست؛ در مدل فروشگاهی وبینو، **ثبت فروش POS با تحویل کالا** معادل تحقق فروش گرفته می‌شود.

### اجزای یک فروش کامل در دفتر

| جزء | بدهکار | بستانکار |
|-----|--------|----------|
| وجه/طلب | صندوق / کارتخوان / چک دریافتنی / دریافتنی مشتری | — |
| درآمد | — | درآمد فروش |
| تخفیف | تخفیف فروش (یا کاهنده درآمد) | — |
| اعتبار باشگاه | هزینه وفاداری | — |
| بهای تمام‌شده | بهای تمام‌شده فروش | موجودی (کاتالوگ/مواد/ساخته) |

### انواع پرداخت فروش

| نوع | اثر |
|-----|-----|
| نقد | صندوق (`11101`) |
| کارت | کارتخوان در راه (`11102`) تا تطبیق |
| چک | چک دریافتنی |
| نسیه / قسط | حساب دریافتنی مشتری |
| ترکیبی | ترکیب موارد بالا |

### مالیات عملکرد

فروش مشمول درآمد ابرازی است. مستند: فاکتور/رسید کارتخوان/سامانه مؤدیان.

### تصمیم وبینو

- فروش سند خودکار می‌سازد.  
- تخفیف → `412`؛ وفاداری → `613`.  
- COGS هم‌زمان با فروش.

## 6. وصول، نسیه، اقساط

### اصل

وصول طلب **دوباره درآمد نیست**. فقط جابه‌جایی دارایی:

- بدهکار نقد/کارت  
- بستانکار دریافتنی  

### تسویه نسیه و تطبیق

پول وصول‌شده تا تطبیق روزانه نباید مستقیم حساب بانکی را شارژ کند (مثل فروش کارت):  
نقد → صندوق، کارت → کارتخوان؛ بعد از تطبیق → حساب بانکی.

### تصمیم وبینو

- `debt_settle` / `debt_payment` / `installment_pay` از مسیر صندوق/POS.  
- حساب انتخابی کاربر = مقصد واریز پس از تطبیق، نه شارژ آنی بانکی.

## 7. خرید، موجودی، فاکتور تأمین‌کننده

### اصل استاندارد ۸

خرید کالا/مواد تا فروش یا مصرف:

- **دارایی موجودی** است، نه هزینه جاری.  
- بهای تمام‌شده خرید = بهای خرید + مخارج مستقیم حمل/گمرک − تخفیف تجاری.  
- ارزشیابی: **اقل بها و خالص ارزش فروش**.

### پرداخت فاکتور خرید

| روش | بستانکار معمول |
|-----|----------------|
| نقد از حساب | حساب بانکی/تنخواه |
| چک | چک پرداختنی |
| نسیه | حساب پرداختنی |
| ترکیبی | ترکیب + مانده AP |

کل مبلغ قابل پرداخت (پایه + VAT در مدل پرداخت) باید با یک منطق پرداخت بسته شود؛ VAT را جدا نسیه نگذارید وقتی کاربر کل را نقد زده.

### لایه‌ها

| لایه | معنی |
|------|------|
| مبلغ پایه فاکتور | `invoice.amount` |
| VAT | `vat_amount` + سند اعتبار |
| لات عملیاتی | ممکن است واحد شامل VAT برای تمام‌شده تولید باشد |
| دفتر موجودی پس از سند VAT | معمولاً پایه بدون اعتبار قابل تهاتر |

### تصمیم وبینو

- فاکتور → موجودی + پرداخت/بدهی.  
- لات مواد پس از فاکتور با VAT: قیمت واحد می‌تواند شامل VAT شود (تمام‌شده تولید).  
- سند VAT جدا اعتبار `11501` را جدا می‌کند.

## 8. تولید و بهای تمام‌شده ساخت

### اصل

تولید جابه‌جایی داخل موجودی است، نه فروش:

- بدهکار کالای ساخته‌شده  
- بستانکار مواد مصرف‌شده  

بهای واحد ساخته = مواد (+ در آینده دستمزد/سربار اگر مدل گسترش یابد).

### ضایعات عادی در خط تولید

هزینه ضایعات عادی معمولاً به بهای واحدهای سالم جذب می‌شود (حسابداری صنعتی).

### تصمیم وبینو

- فعلاً مدل ساده: مصرف مواد → ساخته با `total_cost` لات‌ها.  
- سربار و دستمزد ساخت جداگانه در درخت هزینه/تولید گسترش‌پذیر است.

## 9. ضایعات و کاهش موجودی

### عادی در برابر غیرعادی (استاندارد ۸)

| نوع | حسابداری | مالیات |
|-----|----------|--------|
| عادی / اجتناب‌ناپذیر تولید | جذب در بهای محصول سالم | متعارف → قابل قبول‌تر |
| غیرعادی / قابل کنترل | هزینه/زیان دوره؛ نه داخل بها موجودی باقی | غیرمتعارف → چالش / رد |
| فاسد شدن انبار فروشگاه | موجودی↓ + زیان/COGS↑ | مستند انبار لازم |

### آیا در «لیست هزینه‌ها» بیاید؟

**خیر.** لیست هزینه‌ها برای خروج به ذینفع بابت خدمات/حقوق/قبوض است.  
ضایعات اصلاح انبار است و باید در **سود و زیان از مسیر بهای تمام‌شده یا زیان ضایعات** دیده شود.

### تصمیم وبینو

```
بدهکار  ۵۱۱ (یا معین ضایعات)
بستانکار موجودی مواد/ساخته
```

- منبع: `inventory_waste`  
- **بدون** ردیف در `expenses`  
- نگاشت: `inventory_waste.cogs` → `511`

## 11. هزینه‌های عملیاتی و حقوق

### چه چیزی «هزینه» ماژول هزینه‌ها است؟

| هست | نیست |
|-----|------|
| اجاره، آب، برق، اینترنت | خرید کالای قابل فروش (موجودی) |
| حقوق و دستمزد / مساعده | ضایعات انبار |
| تعمیرات، تبلیغات، متفرقه خدمات | انتقال بین صندوق و بانک |
| اعطای اعتبار دستی باشگاه (مدل خاص) | واریز تطبیق |

### حقوق

- هزینه دوره استخدامی؛ قابل قبول در چارچوب ۱۴۸ با لیست بیمه/حقوق.  
- اگر ماه فیش داخل دورهٔ بسته‌شده باشد و پرداخت بعداً انجام شود: سند هزینه روی **تاریخ دورهٔ باز (روز پرداخت)** تا قفل نشکند؛ توضیح دوره فیش در عنوان.

### سرمایه در برابر جاری

- مخارج سرمایه‌ای → دارایی (`12101`) نه هزینه جاری.  
- استهلاک طبق ماده ۱۴۹ / جدول مصوب (اگر پیاده شد).

### تصمیم وبینو

- هزینه → گروه ۶؛ حقوق → `612`.  
- اتصال اختیاری به معین درخت برای هزینه.

## 12. چک، ظهرنویسی، پیش‌پرداخت ذینفع

### چک دریافتنی

- دریافت: دارایی چک دریافتنی (+ درآمد یا کاهش طلب بسته به منبع).  
- وصول بانکی: خروج از چک دریافتنی → صندوق تا تطبیق → سپس بانک.  
- **وصول چک دریافتی نباید مستقیم بانک را شارژ کند** (همان الگوی تطبیق).

### چک پرداختنی

- صدور بابت خرید/هزینه: بدهی چک.  
- پاس شدن: بستن چک پرداختنی + خروج از حساب بانکی.

### ظهرنویسی

چک دریافتنی بابت بدهی تأمین‌کننده:

- بدهکار AP (و مازاد → پیش‌پرداخت ذینفع)  
- بستانکار چک دریافتنی  

بدون حرکت نقد.

### تصمیم وبینو

کلیدهای `cheque_*` و `beneficiary_advance.*` در نگاشت.

## 13. صندوق، کارتخوان، تطبیق روزانه، حساب بانکی

### نقش حساب‌ها

| حساب | نقش |
|------|-----|
| صندوق (`11101`) | نقد عملیاتی فروشگاه |
| کارتخوان در راه (`11102`) | وجوه کارت تا واریز |
| حساب بانکی / تنخواه | موجودی واقعی بانک/تنخواه پس از واریز/برداشت |

### تطبیق روزانه

واریز اعلام‌شده به حساب:

1. بدهکار حساب بانکی  
2. بستانکار کارتخوان (اولویت) سپس صندوق  

موجودی عملیاتی حساب بانکی از واریزها − هزینه‌ها/فاکتورهای نقد از همان حساب محاسبه می‌شود؛ وصول نسیه/چک نباید قبل از تطبیق آن را باد کند.

## 14. مالیات بر ارزش افزوده (VAT)

### منطق قانون VAT

1. فروش مشمول → مالیات فروش (بدهی به سازمان).  
2. خرید برای فعالیت اقتصادی → **اعتبار مالیاتی** قابل کسر از مالیات فروش.  
3. مازاد اعتبار → انتقال به دوره بعد یا استرداد (شرایط قانون).  
4. اگر اعتبار قابل تهاتر/استرداد نباشد → می‌تواند هزینه قابل قبول ق.م.م شود (تبصره ۵ ماده ۸ قانون VAT).  
5. خرید مربوط به عرضه معاف معمولاً اعتبار ندارد (با استثناهایی مثل ماشین‌آلات خط تولید طبق قانون).

### ثبت دفتر فروشگاهی

| رویداد | بدهکار | بستانکار |
|--------|--------|----------|
| خرید + VAT قابل تهاتر | موجودی (پایه) + اعتبار VAT | نقد/AP (قابل پرداخت) |
| فروش + VAT خروجی (اگر فعال) | نقد/طلب (جمع با VAT) | درآمد + VAT خروجی |

### تصمیم وبینو

- اعتبار خرید: `11501` با سند جدا `invoice_vat` / `expense_vat`.  
- خروجی فروش: کد `21301` برای توسعه آینده.  
- تمام‌شده عملیاتی لات می‌تواند شامل VAT باشد؛ دفتر مالیاتی اعتبار را جدا نگه می‌دارد.

## 15. سامانه مؤدیان و صورتحساب الکترونیکی

- فروش مشمول باید در چارچوب پایانه‌های فروشگاهی / سامانه مؤدیان صورتحساب داشته باشد (بر اساس تکلیف مؤدی).  
- **اعتبار VAT خرید** به‌تدریج فقط با صورتحساب الکترونیکی پذیرفته می‌شود (تاریخ‌های بخشنامه را از متن رسمی روز چک کنید).  
- **هزینه قابل قبول عملکرد** نیز به سمت الزام صورتحساب الکترونیکی می‌رود (دوره گذار جدا از VAT است).  
- در وبینو ماژول مؤدیان زیر حسابداری است؛ باید با فاکتور فروش دفتر هم‌خوان بماند.

## 16. هزینه قابل قبول مالیات عملکرد (۱۴۷ و ۱۴۸)

### ماده ۱۴۷ — چهار شرط اصلی

1. متعارف  
2. مستند  
3. منحصراً برای تحصیل درآمد  
4. متعلق به دوره مالی مربوط  

+ رعایت نصاب و تبصره‌ها (از جمله پرداخت بانکی برای مبالغ بالا).

### ماده ۱۴۸ — مصادیق (نمونه کاربردی فروشگاه)

- بهای تمام‌شده کالای فروش‌رفته / مواد مصرفی  
- حقوق و دستمزد و بیمه مرتبط  
- اجاره محل کسب  
- آب، برق، گاز، ارتباطات مرتبط با فعالیت  
- بیمه دارایی‌های شغلی  
- ضایعات/افت **متعارف** در چارچوب رویه رسیدگی  
- استهلاک طبق مقررات  

### ردهای رایج

- هزینه شخصی مالک  
- بدون مدرک  
- مربوط به درآمد معاف  
- بیش از عرف بدون توجیه  
- ضایعات غیرعادی بدون مستند

## 17. دفاتر و تکالیف ماده ۹۵

صاحبان مشاغل بر اساس نوع/حجم فعالیت گروه‌بندی می‌شوند (گروه اول/دوم/سوم — آستانه‌ها در آیین‌نامه به‌روز می‌شود).

| مفهوم | معنی |
|-------|------|
| دفتر روزنامه | ثبت رویدادها به ترتیب تاریخ |
| دفتر کل | ثبت بر حسب سرفصل حساب |
| سند حسابداری | تجزیه بدهکار/بستانکار متکی به مدرک |
| اظهارنامه | فرم درآمد/هزینه/دارایی برای سازمان |

وبینو با اسناد دوطرفه و دفتر حساب، زیرساخت دفتر کل مکانیزه را می‌دهد؛ تکلیف قانونی گروه مؤدی را کاربر باید بداند.

## 18. بستن دوره، قفل، حسابرس، تعدیل سنواتی

### بستن حساب‌های موقت

1. بستن درآمدها → خلاصه سود و زیان  
2. بستن بها و هزینه‌ها → خلاصه سود و زیان  
3. مانده خلاصه → **سود (زیان) انباشته**  

در وبینو سند `year_close` / بستن میان‌دوره همین کار را روی کدهای موقت انجام می‌دهد → `35`.

### قفل

ثبت یا برگشت عادی با تاریخ ≤ تاریخ بستن ممنوع است.

### مسیرهای مجاز بعد از بستن

| نیاز | مسیر |
|------|------|
| پرداخت حقوق ماه بسته‌شده | سند در دوره باز با توضیح |
| اصلاح اشتباه در دوره بسته | حسابرس + دلیل + تکمیل بستن در صورت نیاز |
| اثر مستقیم روی انباشته بدون باز کردن موقت‌ها | تعدیل سنواتی (مسیر حسابرس) |
| اشتباه بستن | فقط برگشت آخرین بستن (با قواعد سیستم) |

## 20. گزارش‌ها: تراز، دفتر، سود و زیان، ترازنامه

| گزارش | سؤال کاربر |
|-------|------------|
| تراز آزمایشی | آیا دفتر متوازن است و مانده‌ها چیست؟ |

## 22. چک‌لیست طراحی ویژگی جدید

1. رویداد دارایی است، بدهی، درآمد، بها، یا هزینه؟  
2. در UI کدام لیست؟ (هزینه / فاکتور / ضایعات / فروش / …)  
3. تاریخ سند در دوره باز می‌ماند؟  
4. VAT دارد؟ اعتبار جدا یا داخل بها؟  
5. موجودی کم/زیاد می‌شود؟ روش بها (FIFO) چیست؟  
6. آیا باید در P&L دیده شود یا فقط ترازنامه؟  
7. مستند مالیاتی و مؤدیان لازم است؟  
8. کلید نگاشت در `AccountingPostingMapRegistry`؟  
9. این سند مرجع آپدیت شد؟

## 25. پیوست‌ها

### پیوست A — واژه‌نامه

| واژه | معنی |
|------|------|
| COGS | بهای تمام‌شده کالای فروش‌رفته / خروج موجودی |
| NRV | خالص ارزش فروش |
| AP / AR | پرداختنی / دریافتنی |
| حساب موقت | درآمد، بها، هزینه — بسته می‌شود |
| حساب دائم | ترازنامه‌ای |
| اعتبار VAT | مالیات خرید قابل کسر |
| مؤدیان | سامانه صورتحساب الکترونیکی |
| دوره بسته | تا تاریخ بستن قفل ثبت عادی |
| لات | خرید مواد با قیمت واحد FIFO |

### پیوست B — الگوی سندهای پرتکرار وبینو

**فروش نقد+کارت**

```
بدهکار صندوق / کارتخوان
بستانکار درآمد
بدهکار بهای تمام‌شده
بستانکار موجودی
```

**فاکتور خرید نسیه با VAT**

```
بدهکار موجودی (پایه)
بدهکار اعتبار VAT
بستانکار پرداختنی (پایه+VAT)
(+ سند جدا انتقال VAT از موجودی موقت به اعتبار، طبق مدل فعلی)
```

**هزینه نقد**

```
بدهکار هزینه جاری/حقوق
بستانکار حساب بانکی/صندوق
```

**ضایعات**

```
بدهکار بهای تمام‌شده
بستانکار موجودی
```

**تطبیق واریز**

```
بدهکار حساب بانکی
بستانکار کارتخوان و/یا صندوق
```

**بستن دوره (ساده)**

```
بدهکار درآمدها
بستانکار خلاصه/انباشته
بدهکار انباشته
بستانکار بها و هزینه‌ها
(پیاده‌سازی وبینو مستقیماً به سود انباشته جمع می‌کند)
```

| ۱۴۰۴/۰۸ | وصول نسیه/چک دریافتی تا تطبیق به صندوق/POS |
| ۱۴۰۴/۰۸ | پرداخت کل فاکتور (پایه+VAT) یکپارچه |

| ۱۴۰۴/۰۸ | پرداخت حقوق بعد از بستن → تاریخ دوره باز |
